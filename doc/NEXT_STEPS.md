# Arkoala effort

## Main goals

   * Rework UI framework to make it future ready
     * Controlled API surface (API and implementation are consistent and proven correct)
     * Multiple languages (including ArkUI NEXT and CJ) support
     * C API as the main entry point for UI engine
     * UI DSL processed by general purpose compiler and generic syntax constructions
     * Improve architecture by separation of concerns between UI core, components and graphics layers
   * Provide higher performance of UI execution
     * Apply incremental computations engine to UI builder functions evaluation
     * High performance automatically generated interop glue code
     * Use strongly typed high performance AOTed language for both user and engine code
   * Simplify user model of the UI code
     * Reduce number of state primitives
     * Get rid of artificial limitations in builder functions syntax
     * Obsolete hard-coded builder/state connection via 'struct'
   * Provide consistent layered API for the UI engine
      * UI builders DSL
      * nodes manipulation managed API
      * fully functional pure C API

## Current status

   * Implemented TypeScript-based full stack solution using manually implemented subset of C API
   * Full C API is being actively developed, with tests coverage and full functionality
   * Several issues were identified in the ACE engine and fixed or reported
   * Development of C API happens in upstream branch, merge to master to be done
   * Managed bindings for TS and ArkTS NEXT are generated by IDLize project
   * 2 VMs (HZ + Panda) proof of concept execution configuration works
   * ArkTS NEXT component API for the whole SDK is available

# IDLize effort

## Main goals

   * Make OpenHarmony a multi-language programming environment
   * Describe all system interfaces in language neutral interface description language (IDL)
   * Generate glue code for all supported languages from IDL automatically
     * Universal language-neutral backends: TypeScript, ArkTS NEXT, CJ, Java, C++
     * Most generators expressed in language-neutral manner
     * Multi-target Koala interop mechanisms are supported for FFI
   * Provide powerful automated mechanisms for all code maintenance tasks:
     * documentation generation
     * API style checks
     * API compatibility checks
     * tests generation
     * task and progress tracking
   * Ensure extendible architecture of the generator tool, with stable core and per-project generators

## Current status

   * Implemented functional version of following tools:
      * TypeScript API linter, runnable on full OHOS API
      * TypeScript API to IDL convertor, runnable on full OHOS API
      * IDL managed bindings for ArkUI
        * for TypeScript: fully works
        * for ArkTS: mostly works, modulo ArkTS compiler issues
        * for CJ: converts API subset
        * for Java: experimental, converts API subset
      * IDL managed bindings for other OHOS APIs
         * C API generator done
         * Managed APIs generator is progress (shares the same common language writers ecosystem, so all supported languages are there)
